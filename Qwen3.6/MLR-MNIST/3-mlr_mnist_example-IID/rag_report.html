File descriptions

client_app.py

This Python file defines a Flower ClientApp for a federated learning system using PyTorch, specifically tailored for an MNIST classification task. It implements the core logic for both training and evaluation phases of a federated learning workflow. The client receives global model weights from the server, performs local training or evaluation on its partitioned data, updates its local state with the new model weights, and returns updated model parameters and metrics (such as loss and accuracy) back to the server. The client handles device placement (CPU/GPU), manages local model persistence via state dictionaries, and supports configurable training parameters like local epochs and learning rate. The structure allows for modular and reusable components through helper functions for loading and saving model states, as well as separate training and testing functions defined in an external task.py module. This client application integrates seamlessly with the Flower framework to participate in distributed model training across multiple clients.

server_app.py

This Python file defines the main server application for a federated learning system using the Flower framework. It initializes and configures a federated training process where a global model is trained across multiple clients over several rounds. The server loads a global model, sets up a custom strategy for federated averaging (FedAvg), and manages the training loop by coordinating client participation and model aggregation. It also handles evaluation of the global model at each round using a predefined test dataset stored locally on the server, and saves the final trained model to disk after completion. The server uses configuration parameters such as number of rounds, client fractions for training and evaluation, and device settings to control the training process.

strategy.py

This file defines a custom federated learning strategy named CustomStrategy that extends the standard FedAvg algorithm from Flower. Its primary purpose is to enhance the basic federated averaging process by adding functionalities such as saving model checkpoints when better accuracy is achieved, logging training and evaluation metrics to both local JSON files and Weights & Biases (W&B), and implementing a simple learning rate scheduling mechanism. The strategy manages the complete lifecycle of a federated training session, including client-side training, server-side evaluation, and centralized model updates, while maintaining detailed logging and result persistence across training rounds.

task.py

This Python file defines a PyTorch-based implementation for federated learning using the Flower framework, specifically tailored for an MNIST-like dataset. It includes the neural network architecture (Net), training and testing functions (train, test) that operate on PyTorch data loaders, custom dataset loading via NPZDataset, and utility functions for creating run directories and loading partitioned data from local .npz files. The structure supports distributed training across multiple clients by loading client-specific subsets of data and performing local model updates. The file also handles device placement (CPU/GPU), data transformations, and evaluation metrics such as loss and accuracy. This setup enables federated learning experiments with a focus on partitioned data handling and model training/validation processes.
